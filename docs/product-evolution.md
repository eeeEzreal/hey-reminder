# Hey! 产品演进

本文件只记录 Hey! 为什么发生重要变化；具体代码改动由 Git History 记录。通常一件事情一句话，同一产品变化不因涉及文件较多而展开为开发流水账。

最初产品灵感提出时间：**待确认**。当前仓库可核验历史始于 2026-09-21，不据此反推灵感日期。

## 记录规则

- 记录重要灵感、产品决策、方向变化、关键功能落地和重要方案替代。
- 明确标注“灵感”“决策”或“实现”；同日完成时可合并标注。
- 日期必须有真实依据；只能确认月份时写到月份，无法确认时标记“待确认”。
- 普通 Bug、小型 UI 调整、变量改名、Lint 和格式化不记录。
- 重要演进完成并验证后，默认在末尾追加 1～3 行。

## 可核验演进

- 2026-09-21｜决策并实现｜Hey! 以本地、无账号、轻量提醒为边界建立 Android 工程，并确定使用 UsageStats、`specialUse` 前台服务和纯 Kotlin 状态机，避免 AccessibilityService 与复杂后端。（`8c7b51c`）
- 2026-09-21｜实现｜完成 Usage Access 的用途说明、系统设置跳转和返回后状态刷新，建立实际前台检测所需的最低权限入口。（`13bd4e0`）
- 2026-09-21｜决策并实现｜新增按本地日期保存的提醒次数结构，并明确只有真正成功触发提醒才能计数，为后续周/月汇总保留按日数据。（`3492766`）
- 2026-09-21｜决策并实现｜App 名单聚焦用户可启动的应用，以 launcher intent `<queries>` 替代范围更大的 `QUERY_ALL_PACKAGES`，选择结果仅保存在本机。（`e6eeeb7`）
- 2026-09-22｜实现｜根据新版品牌视觉将图标更新为桃橙至珊瑚粉渐变、米白描边感叹号的原生 Adaptive Icon。（`d8e1756`）
- 2026-09-22｜实现｜前台 App 检测与连续使用计时合并落地：切换、离开或锁屏立即重置，每个会话只产生一次阈值事件，尚不发送提醒通知也不增加提醒次数。（`7cf007f`）
- 2026-09-23｜决策｜项目采用轻量“项目考古 + `docs/product-evolution.md`”记录方式，用真实证据区分灵感、决策与实现，并在后续重要演进验证后默认同步更新。
